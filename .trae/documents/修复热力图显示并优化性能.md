# 修复热力图显示并优化性能

## 问题分析
1. Dashboard中的"Heatmap View"显示全黑
2. 当前实现使用CPU进行热力图可视化，存在Device->Host->Device的内存拷贝开销
3. 需要实现全GPU流水线，使用CUDA Kernel进行伪彩色映射，通过CUDA-OpenGL Interop直接更新纹理

## 实现步骤

### 1. 新增CUDA Kernel
- 创建`common/kernels.cu`文件
- 实现将float(0.0-1.0)映射为Jet伪彩色(RGB)的核函数
- 包含`clamp`辅助函数、`floatToJet`颜色映射函数和`applyColorMapKernel`主核函数
- 实现`launchApplyColorMap`包装函数用于调用核函数

### 2. 修改FrameTask结构体
- 在`pipeline/FrameTask.h`中添加`DeviceBuffer d_heatmap_gpu = nullptr;`成员变量，用于存储GPU上的热力图RGB数据

### 3. 修改PostProcessor
- 在`postprocessor.cpp`中添加外部声明：`extern void launchApplyColorMap(float* d_map, void* d_out_rgb, int w, int h, cudaStream_t stream);`
- 在`process`方法中移除CPU OpenCV逻辑
- 申请GPU显存并调用CUDA Kernel生成热力图RGB数据
- 确保使用`cudaStreamSynchronize`同步流

### 4. 修改Dashboard
- 在`dashboard.h`中添加`#include <cuda_gl_interop.h>`和`cudaGraphicsResource_t cuda_res_heatmap = nullptr;`成员变量
- 在`InitResources`方法中注册纹理为CUDA资源
- 在析构函数中释放CUDA资源
- 在`UpdateData`方法中使用CUDA-OpenGL Interop直接从显存更新纹理
- 使用`cudaGraphicsMapResources`和`cudaGraphicsUnmapResources`管理资源映射
- 使用`cudaMemcpy2DToArray`实现GPU到GPU的直接拷贝

## 预期效果
1. "Heatmap View"将显示正确的伪彩色热力图
2. 移除了Device->Host->Device的内存拷贝，提升性能
3. 实现了全GPU流水线，从异常图计算到纹理显示完全在GPU上完成
4. 通过CUDA-OpenGL Interop实现了高效的纹理更新

## 技术要点
- CUDA Kernel编程实现伪彩色映射
- CUDA-OpenGL Interop实现直接纹理更新
- 智能指针管理GPU内存
- 异步流操作优化性能
- 确保资源正确释放，避免内存泄漏

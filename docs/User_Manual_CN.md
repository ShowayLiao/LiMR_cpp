# 用户手册

## 1. 系统概述

### 1.1 简介

AnomaRT 是 anomalib-runtime 的桌面应用：一个基于 TensorRT 的原生实时异常检测与视频流分析运行时。本用户手册提供仪表板操作、系统启动、接口定义和 ONNX 导出要求。

### 1.2 主要功能

- 实时视频异常检测
- 直观的仪表板界面
- 支持单引擎和双引擎推理模式
- 异常热图生成
- 可配置的检测阈值
- 多种分辨率支持

## 2. 系统启动

### 2.1 前提条件

启动系统前，请确保满足以下要求：

- Windows 10/11 操作系统
- 兼容的 NVIDIA GPU 和驱动
- 包含全部 DLL 的完整 AnomaRT 发布目录

终端用户不需要单独安装 CUDA Toolkit、TensorRT SDK 或 OpenCV。

### 2.2 启动步骤

1. **准备可执行文件**
   - 导航到解压后的 AnomaRT 发布目录
   - 确保所有必需的 DLL 文件都存在（详情请参见开发者手册）

2. **运行应用程序**
   - 双击 `AnomaRT.exe` 启动系统
   - 仪表板窗口将出现

3. **初始化系统**
   - 在仪表板中配置所需参数（详情见第 3 节）
   - 点击 "INITIALIZE SYSTEM" 按钮
   - 等待初始化过程完成

4. **开始处理**
   - 初始化后，系统将自动开始处理
   - 如果暂停，点击 "RESUME" 开始处理

## 4. 输入/输出接口

### 4.1 输入接口

#### 4.1.1 视频输入

| 输入类型 | 描述 |
|----------|------|
| **视频文件** | 支持格式：MP4、AVI 等 |
| **摄像头** | USB 摄像头、网络摄像头 |
| **RTSP 流** | 通过 RTSP 协议的网络视频流 |

#### 4.1.2 模型输入

| 参数 | 描述 |
|------|------|
| **输入张量** | 形状：[1, 3, H, W]，其中 H 和 W 是模型输入维度 |
| **数据类型** | F32 或 F16（取决于模型精度） |
| **归一化** | 图像像素值归一化到 [-1, 1] 范围 |

### 4.2 输出接口

#### 4.2.1 热图输出

| 输出类型 | 描述 |
|----------|------|
| **异常热图** | 形状：[1, 1, H, W]，值表示异常分数 |
| **可视化** | 颜色编码的热图，红色表示高异常区域 |

#### 4.2.2 检测结果

| 输出类型 | 描述 |
|----------|------|
| **异常分数** | 表示整体异常水平的单一值（0.0-1.0） |
| **缺陷位置** | 检测到的超过阈值的异常坐标 |
| **状态标志** | 指示是否检测到异常的布尔值 |



## 5. ONNX 导出要求

### 5.1 模型要求

为确保与 AnomaRT 兼容，模型在导出为 ONNX 格式时必须满足以下要求：

| 要求 | 描述 |
|------|------|
| **输入形状** | 固定输入形状：[1, 3, H, W]，其中 H 和 W 是 32 的倍数 |
| **输出形状** | 固定输出形状：[1, 1, H, W] 用于热图生成 |
| **数据类型** | Float32（可在 TensorRT 优化期间转换为 Float16） |
| **归一化** | 模型应期望输入归一化到 [-1, 1] 范围 |

### 5.2 导出过程

#### 5.2.1 PyTorch 模型导出

```python
# 导出 PyTorch 模型到 ONNX 的示例代码
import torch
import torch.nn as nn

# 加载训练好的模型
model = YourModel()
model.load_state_dict(torch.load('model.pth'))
model.eval()

# 创建虚拟输入
dummy_input = torch.randn(1, 3, 256, 256)  # 根据需要调整大小

# 导出到 ONNX
torch.onnx.export(
    model,
    dummy_input,
    'model.onnx',
    export_params=True,
    opset_version=11,
    do_constant_folding=True,
    input_names=['input'],
    output_names=['output'],
    dynamic_axes={'input': {2: 'height', 3: 'width'}, 'output': {2: 'height', 3: 'width'}}  # 可选的动态轴
)
```

#### 5.2.2 TensorRT 转换

将模型导出到 ONNX 后，需要将其转换为 TensorRT 引擎格式：

1. **使用 TensorRT ONNX 解析器**
   - 系统在初始化期间自动将 ONNX 模型转换为 TensorRT 引擎
   - 或者，您可以使用 TensorRT `trtexec` 工具进行离线转换

2. **离线转换命令**
   ```bash
   # 转换 ONNX 到 TensorRT 引擎的示例命令
   trtexec --onnx=model.onnx --saveEngine=model.engine --fp16
   ```

### 5.3 模型兼容性

| 模型类型 | 兼容性 | 说明 |
|----------|--------|------|
| **Anomalib 模型** | 完全兼容 | 推荐使用以获得最佳结果 |
| **自定义自编码器** | 兼容 | 必须遵循输入/输出要求 |
| **其他异常模型** | 兼容 | 可能需要调整以满足输入/输出规范 |

## 6. 故障排除

### 6.1 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| **无法打开视频源** | 无效的视频路径或摄像头 ID | 检查视频文件路径或摄像头连接 |
| **模型加载失败** | 不兼容的 ONNX 模型或缺少依赖项 | 验证模型格式并检查 TensorRT 安装 |
| **GPU 内存不足** | 分辨率过高或模型过大 | 降低分辨率或使用更小的模型 |
| **检测精度低** | 阈值调整不当 | 微调缺陷阈值参数 |
| **处理速度慢** | 使用 FP32 精度或高分辨率 | 切换到 FP16 精度或降低分辨率 |

### 6.2 错误消息

| 错误消息 | 描述 | 解决方案 |
|----------|------|----------|
| **CUDA error: out of memory** | GPU 内存不足 | 降低分辨率或使用更小的模型 |
| **Could not open video device** | 摄像头未检测到或无法访问 | 检查摄像头连接和权限 |
| **ONNX parser error** | 无效的 ONNX 模型格式 | 确保模型已正确导出 |
| **TensorRT initialization failed** | 不兼容的 TensorRT 版本 | 安装推荐的 TensorRT 版本 |

## 7. 最佳实践

### 7.1 性能优化

| 建议 | 描述 |
|------|------|
| **使用 FP16 精度** | 显著提高处理速度，同时精度损失最小 |
| **优化分辨率** | 在处理速度和检测精度之间取得平衡 |
| **预转换模型** | 使用 `trtexec` 预转换 ONNX 模型以加快启动速度 |
| **关闭不必要的应用程序** | 释放 GPU 内存以获得更好的性能 |

### 7.2 检测优化

| 建议 | 描述 |
|------|------|
| **校准阈值** | 根据特定应用要求调整阈值 |
| **使用适当的模型** | 根据所需的精度和速度选择模型大小 |
| **考虑光照条件** | 确保一致的光照以获得可靠的检测 |
| **定期更新模型** | 定期使用新数据重新训练模型 |

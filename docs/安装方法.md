# 编译与安装指南

本文说明如何在 Windows 上从源码编译当前 C++ 版本的 FastVision。文中的命令和
依赖版本均以当前 `CMakeLists.txt` 及本仓库已经使用的构建环境为依据。

> 当前项目**不依赖** LibTorch、cuDNN、`opencv_contrib`，也不要求启用 CUDA
> 的 OpenCV。GPU 加速由 CUDA、NPP、TensorRT 和 CUDA-OpenGL 互操作直接实现。

## 1. 支持及已验证环境

FastVision 当前面向 Windows x64。

| 组件 | 已验证版本 | 说明 |
| --- | --- | --- |
| Windows | Windows 10 x64 | 使用兼容工具链时，Windows 11 通常也可构建 |
| Visual Studio | Visual Studio 2019 16.x | MSVC v142、x64、C++17 |
| CMake | 3.15.7 | 项目声明的最低版本为 3.10 |
| CUDA Toolkit | 11.6 | 当前构建缓存使用 `nvcc` 11.6 |
| TensorRT | 10.12.0.36 | Windows x64、TensorRT 10 库 |
| OpenCV | 4.5.5 | Release 共享库 |
| GPU | 支持 CUDA 的 NVIDIA GPU | 需要兼容的 NVIDIA 驱动 |

以上组合是当前已验证环境。其他版本可能也能工作，但 CUDA、Visual Studio、
TensorRT、OpenCV 以及生成的 TensorRT engine 必须相互兼容。

## 3. 安装编译器和构建工具

### 3.1 Visual Studio 2019

安装 Visual Studio 2019 时，勾选 **使用 C++ 的桌面开发** 工作负载，并确认
包含以下组件：

- MSVC v142 C++ x64/x86 生成工具
- Windows 10 SDK
- 用于 Windows 的 C++ CMake 工具（已安装独立 CMake 时可不选）

已验证的 CUDA 11.6 环境使用 CMake 生成器 `Visual Studio 16 2019`。如果改用
Visual Studio 2022，需要同时使用支持 v143 工具链的 CUDA Toolkit 和 OpenCV，
并修改 CMake 生成器。

### 3.2 CMake

安装 Windows x64 版本的 CMake，并在安装界面选择将 CMake 添加到系统
`PATH`。

验证安装：

```powershell
cmake --version
```

### 3.3 NVIDIA 驱动与 CUDA Toolkit

建议先安装 Visual Studio，再安装 CUDA，以便 CUDA 安装程序正确注册 Visual
Studio 集成。

先安装支持所选 CUDA Toolkit 的 NVIDIA 驱动，再安装 CUDA 11.6。默认安装选项
通常已经足够。

验证安装：

```powershell
nvidia-smi
nvcc --version
```

如果找不到 `nvcc`，请将 CUDA 的 `bin` 目录加入 `PATH`，例如：

```text
C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v11.6\bin
```

## 4. 安装 TensorRT

1. 下载与 CUDA 环境匹配的 Windows x64 TensorRT 10 压缩包。已验证版本为
   `TensorRT-10.12.0.36`。
2. 解压到固定目录，例如：

   ```text
   C:\deps\TensorRT-10.12.0.36
   ```

3. 确认解压目录中包含：

   ```text
   include\NvInfer.h
   lib\nvinfer_10.lib
   lib\nvinfer_10.dll
   lib\nvonnxparser_10.lib
   samples\common
   ```

TensorRT 根目录通过 `TRT_DIR` 传给 CMake。不要把 `TRT_DIR` 指向其 `include`
或 `lib` 子目录。

如果需要在构建目录以外从命令行运行程序，请把 TensorRT 的 `lib` 目录加入
`PATH`：

```text
C:\deps\TensorRT-10.12.0.36\lib
```

## 5. 安装 OpenCV

当前项目使用 OpenCV 完成图片/视频读写和 CPU 侧图像操作，不需要启用 CUDA
的 OpenCV，也不需要 `opencv_contrib`。

### 方案 A：使用已有的兼容 OpenCV 4.5.5

将 `OpenCV_DIR` 设置为包含 `OpenCVConfig.cmake` 的目录。已验证的目录结构为：

```text
C:\opencv_s\build\install
├── OpenCVConfig.cmake
└── x64\vc16\bin
```

### 方案 B：编译精简的 OpenCV 4.5.5 共享库

解压 OpenCV 4.5.5 源码后执行：

```powershell
cmake -S C:\deps\opencv-4.5.5 `
      -B C:\deps\opencv-4.5.5-build `
      -G "Visual Studio 16 2019" -A x64 `
      -DCMAKE_INSTALL_PREFIX=C:\deps\opencv-4.5.5-install `
      -DBUILD_SHARED_LIBS=ON `
      -DBUILD_TESTS=OFF `
      -DBUILD_PERF_TESTS=OFF `
      -DBUILD_EXAMPLES=OFF

cmake --build C:\deps\opencv-4.5.5-build `
      --config Release `
      --target INSTALL
```

将生成的安装根目录作为 `OpenCV_DIR`：

```text
C:\deps\opencv-4.5.5-install
```

如果 OpenCV DLL 不在 `x64\vc16\bin`，请把实际 DLL 目录加入 `PATH`。项目当前
的构建后复制逻辑按已验证的 OpenCV 4.5.5/vc16 目录结构查找 DLL。

## 6. 获取并检查项目源码

克隆仓库，或解压完整的源码包：

```powershell
git clone <repository-url>
cd inference_LiMR
```

### 6.1 下载 GLFW 和 Dear ImGui

当前源码已使用 GLFW 3.4 和 Dear ImGui 1.92.5 验证。在仓库根目录执行：

```powershell
New-Item -ItemType Directory -Force 3rdparty
git clone --branch 3.4 --depth 1 `
    https://github.com/glfw/glfw.git 3rdparty/glfw
git clone --branch v1.92.5 --depth 1 `
    https://github.com/ocornut/imgui.git 3rdparty/imgui
```

也可以使用第 2 节表格中的源码 ZIP 链接。解压后移除目录名中的版本后缀，
整理为以下结构：

```text
3rdparty\
├── glfw\
│   ├── CMakeLists.txt
│   ├── include\
│   └── src\
└── imgui\
    ├── imgui.cpp
    ├── imgui.h
    └── backends\
```

不要在上述路径下再嵌套一层 `glfw-3.4` 或 `imgui-1.92.5`。项目
`CMakeLists.txt` 要求依赖源码根目录必须正好位于 `3rdparty/glfw` 和
`3rdparty/imgui`。

### 6.2 检查源码目录

确认内置 UI 依赖文件存在：

```text
3rdparty\glfw\CMakeLists.txt
3rdparty\imgui\imgui.cpp
3rdparty\imgui\backends\imgui_impl_glfw.cpp
```

如果这些文件缺失，请重新执行上述下载和解压步骤，再运行 CMake。

## 7. 配置项目

打开 **Developer PowerShell for VS 2019**，进入仓库根目录，然后执行：

```powershell
cmake -S . -B build `
      -G "Visual Studio 16 2019" -A x64 `
      -DOpenCV_DIR="C:/deps/opencv-4.5.5-install" `
      -DTRT_DIR="C:/deps/TensorRT-10.12.0.36"
```

请将两个依赖目录替换为实际安装路径。Windows 下向 CMake 传递路径时，建议
使用正斜杠。

如果安装了多个 CUDA Toolkit，可显式指定版本：

```powershell
cmake -S . -B build `
      -G "Visual Studio 16 2019" -A x64 `
      -DOpenCV_DIR="C:/deps/opencv-4.5.5-install" `
      -DTRT_DIR="C:/deps/TensorRT-10.12.0.36" `
      -DCUDA_TOOLKIT_ROOT_DIR="C:/Program Files/NVIDIA GPU Computing Toolkit/CUDA/v11.6"
```

更换 Visual Studio、CUDA、TensorRT 或 OpenCV 后，不要继续复用原构建目录，
请使用新的构建目录重新配置。

## 8. 编译

仅编译主程序：

```powershell
cmake --build build --config Release --target limr
```

编译主程序及全部测试程序：

```powershell
cmake --build build --config Release
```

主程序生成位置：

```text
build\Release\limr.exe
```

现有 `build_test.bat` 引用了已经删除的 `test_single_frame` 目标，不适用于当前
源码，请使用本文提供的 CMake 命令。

## 9. 运行测试

执行已注册的 CTest 测试：

```powershell
Push-Location build
ctest -C Release --output-on-failure
Pop-Location
```

部分契约测试可独立运行；以下测试还需要 GPU 或本地测试资源：

- `heatmap_contract` 需要可用的 CUDA GPU。
- `pipeline_model_contract` 需要
  `input/LiMR_merged.onnx`、`input/IMG_9255.png`、兼容的 TensorRT/CUDA
  动态库以及可用的 NVIDIA GPU。
- `test_input_thread` 会被编译，但目前未注册到 CTest；手动运行时需要
  `input/blade.avi`。

只运行自包含的契约测试：

```powershell
Push-Location build
ctest -C Release --output-on-failure `
      -R "input_shape_contract|safe_queue_contract|engine_contract|file_dialog_contract|dashboard_task_state_contract|dashboard_render_options_contract|anomaly_map_shape_contract"
Pop-Location
```

## 10. 安装或打包

CMake 默认安装目录为 `build\install`。编译安装目标：

```powershell
cmake --build build --config Release --target INSTALL
```

安装后的主程序位于：

```text
build\install\bin\limr.exe
```

编译和安装过程中，CMake 会尝试复制所需的 OpenCV、CUDA/NPP 和 TensorRT
DLL。请检查 CMake 警告；如果某个 DLL 未被自动找到，请将其实际目录加入
`PATH`，或手动复制到 `limr.exe` 所在目录。

## 11. 运行 FastVision

启动 Release 版本：

```powershell
.\build\Release\limr.exe
```

可以在界面中选择输入源和模型。模型输入输出要求参见
[`MODEL_IO.md`](../MODEL_IO.md)。

TensorRT 序列化 engine 文件与 TensorRT 版本、CUDA 版本、GPU 架构和构建
设置有关。如果 engine 无法加载，请使用原始 ONNX 模型在目标环境中重新生成。

## 12. 常见问题

### CMake 找不到 CUDA 编译器

- 从对应 Visual Studio 版本的 Developer PowerShell 运行 CMake。
- 确认 `nvcc --version` 能正常执行。
- 如果先安装 CUDA、后安装 Visual Studio，请修复或重新安装 CUDA Toolkit
  的 Visual Studio 集成。
- 安装多个 CUDA 版本时，显式传入 `CUDA_TOOLKIT_ROOT_DIR`。

### CMake 找不到 OpenCV

将 `OpenCV_DIR` 指向包含 `OpenCVConfig.cmake` 的目录，而不是 OpenCV 源码目录：

```powershell
-DOpenCV_DIR="C:/deps/opencv-4.5.5-install"
```

### 找不到 `nvinfer_10.lib` 或 `nvonnxparser_10.lib`

确认 `TRT_DIR` 指向 TensorRT 解压根目录，并确认其 `lib` 目录同时包含 `.lib`
和 `.dll` 文件。

### 启动程序时提示缺少 DLL

将以下目录加入 `PATH`，或把所需 DLL 复制到主程序旁边：

```text
<OpenCV_DIR>\x64\vc16\bin
<CUDA_ROOT>\bin
<TRT_DIR>\lib
```

典型运行时依赖包括 OpenCV 4.5.5、CUDA runtime/NPP/cuBLAS 和 TensorRT 10
DLL。准确文件名可在 `CMakeLists.txt` 的 `REQUIRED_DLLS` 中查看。

### TensorRT engine 反序列化失败

使用生成该 engine 的同一 TensorRT 主版本，或者在目标机器上从 ONNX 重新
生成。不要把 TensorRT engine 当作可跨环境直接复制的通用模型文件。

### CUDA-OpenGL 互操作失败

- 更新 NVIDIA 驱动。
- 确保程序运行在 NVIDIA GPU 上，而不是集成显卡上。
- 避免通过不提供兼容 OpenGL 上下文的远程桌面环境启动程序。

### 测试因缺少文件而失败

模型流水线测试依赖 `input/` 下的本地文件，这些资源不保证存在于每个源码
副本中。请补充所需资源，或运行上文列出的自包含测试子集。
